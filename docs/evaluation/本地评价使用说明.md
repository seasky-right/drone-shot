# ReachPoint 本地评价使用说明

本地评价链路覆盖 FR-EVL-01 至 FR-EVL-04：读取一次完整的 ReachPoint 过程记录，计算目标、时间、安全与综合成绩，输出 `result.json`；读取多个结果，输出 `summary.json` 和 `report.md`。输入记录可以由后续 Runner/Recorder 产生。本页的演示记录由脚本合成，仅用于验证评价代码。

## 立即运行演示

在仓库根目录，用 Python 3.13 执行以下四条命令。生成物位于被 Git 忽略的 `runs/local_demo/`。

```powershell
python -B -m scripts.generate_reach_point_demo runs/local_demo/records
python -B -m evaluators.cli evaluate-batch runs/local_demo/records --output-dir runs/local_demo/results
python -B -m evaluators.cli summarize runs/local_demo/results --output runs/local_demo/summary.json --report runs/local_demo/report.md
python -B -m unittest discover -s tests -v
```

演示包含两个**合成轨迹标签**、每个标签两次运行。预期 `synthetic_fast` 平均分 `86.5`，`synthetic_slow` 平均分 `74.5`。`runs/local_demo/results/reach-demo/synthetic_fast/0/result.json` 的目标分、时间分和总分分别是 `70`、`18`、`88`。这些标签不是智能体算法，也不是 AirSim 飞行结果。

## 评价自己的记录

单个记录：

```powershell
python -B -m evaluators.cli evaluate path/to/episode.json --output path/to/result.json
```

一个目录中的多份记录可以使用 `evaluate-batch`。结果按 `case_id/agent_id/repeat_index/result.json` 保存；然后用 `summarize` 汇总结果目录。批量输出目录应位于输入目录之外。

输入记录使用 `drone.evaluation.record/v0.1` 格式，字段为 `benchmark_id`、`case_id`、`agent_id`、`episode_id`、`repeat_index`、`task_spec`、`initial_observation`、`steps`、`progress`、`termination_reason`、`events`、`cleanup`、`environment`，以及可选的 `error`。具体 JSON 结构可运行演示生成器后查看 `runs/local_demo/records/synthetic_fast/record-0.json`。

每个 `steps` 元素包含已有平台契约中的 `sequence`、`observation_before`、`action`、`execution`、`observation_after`，以及 `elapsed_monotonic_s`。该时间必须由运行器使用单调时钟从 episode 开始计量，不能填墙上时间或模拟器时间。到达与首次完成时间以动作后的 `observation_after` 为准。`events` 为 `null` 表示安全事件能力不可用；`[]` 表示事件采集完整、确实没有事件。错误终止需要在 `error` 写入结构化 `code`、`message`、`retryable`。

## 输出与比较规则

每次运行的 `result.json` 包含任务配置副本、终止原因、原始指标、`scores.goal/time/total`、安全及排名状态、cleanup、轨迹摘要、Evaluator/评分规则版本、环境信息、异常信息和输入记录路径。没有完整事件数据时，碰撞次数为 `null`，不会伪装成零碰撞。

汇总时，各算法必须拥有**相同的案例和重复编号**，且每组任务配置与环境字段相同。报告保留所有尝试次数及终止原因。后端、评测器、初始化和任务实现错误单独计为基础设施错误；它们不进入算法平均分及成功率分母，出现时暂停排名。安全数据缺失或取消排名资格也暂停排名。碰撞率仅对有碰撞事件数据的样本计算。`score_std` 是总体标准差。

当前实现是离线评价工具。`benchmarks/reach_point_v0_1/` 已固定 1 个案例、3 类 baseline、5 个 seed、计分与重试规则，可运行 `python -B scripts/validate_reach_point_pack.py` 检查。真实任务调度、过程记录采集、AirSim 闭环以及实际执行 `3 Agent × 5 repeats` 尚需 Runner/Experiment Manager 合流。输入记录应来自可信 Recorder；此工具不会验证上传记录是否真实飞行。
