## 1. 本轮目标

先形成可交接的轻量仓库和公共协议基线，再完成一个真实、可记录、可重复的单机任务闭环。之后接搜索任务与多 Agent 比较。

近期不安排 UE5 迁移、新仿真器、多无人机、RL 训练、LLM/VLM、Web 服务和真机。这些保留在整体路线中，不作为本轮启动前提。

总体顺序：

```text
P0 仓库入口与冻结准备
  → P1 Integration 0：公共协议 + 样例 + 契约测试
  → P2 A/B/C 分线实现
  → P3 Integration 1：ReachPoint 真实闭环
  → P4 SearchTarget 能力验证与真实闭环
  → P5 Integration 2：V0.3 重复实验与比较报告
```

这是一组依赖关卡，不按三个人分别“完成自己的 V0.3”后才集成。文中的 A/B/C 表示职责，不是已经确定的 GitHub 账号。

## 5. P2：分线实现一个可合流的小切片

### A：Mock 与运行内核

- 实现 MockBackend、Dummy 组件和 EpisodeRunner。
- 明确每一步的动作前观测、执行结果、动作后观测，以及终止后的最后一次记录。
- 实现 Recorder 和 CLI：成功、超时、Agent/Backend/Task/Evaluator 错误都产生可解释结果。
- 最小产物：`task` 配置副本、`result.json`、轨迹、事件和运行版本信息；图像存独立文件并由元数据引用。
- 检查资源清理：异常退出仍尝试按既定职责完成收尾，收尾失败独立记录，不覆盖最初错误。

验收：无仿真环境可完成一个 Mock episode；成功和失败路径都有结果；任务或 Agent 可以替换而不改 Runner。

### B：完整 AirSimBackend

- 通过现有底层协议适配，补齐连接、reset、状态聚合、动作翻译和关闭。
- 先满足 ReachPoint 所需的起飞、位置移动、悬停、返航和降落；传感器请求按已发现能力执行。
- 补齐完成判定、超时和可配置边界；不能只因 RPC 返回就宣布动作成功。
- 明确旧场景默认载具、配置不可靠读取、原生降落状态缺陷的兼容路径。
- 从原控制台/验收脚本提取行为依据，在新层实现兼容；冻结原件不直接改写。
- 提供独立 smoke test 和运行元数据。近期允许外部启动仿真，再由 Backend 连接；完整进程托管仍属后续阶段。

验收：不依赖 Runner，可经统一接口完成 reset→起飞→航点→采集已确认可用的数据→返航→降落→关闭；深度若不可用明确失败/降级，不伪造成功。

## 6. P3：Integration 1，首次真实合流

组合：AirSimBackend + EpisodeRunner + ReachPointTask + 固定航线 Agent + ReachPointEvaluator。

建议的首个验收任务：在经 B 确认的安全小范围内起飞、到达指定航点、记录状态及可用图像、返航、兼容性降落。具体高度、航点、速度、误差容差与超时写入配置并冻结，本文不把未经现场验证的数值作为已批准参数。

必须同时满足：

- [ ] 同一任务格式可在 Mock 与 AirSim 上执行，切换通过配置完成。
- [ ] Runner 核心不因 Backend 切换而增加 AirSim 特判。
- [ ] Task 的到达判定与最终安全收尾分开记录；起飞成功不等于任务成功。
- [ ] 至少一个成功案例和可控失败案例具有完整结果、轨迹及事件。
- [ ] 最后动作后的状态进入评测；数据可追溯至任务、协议、代码和资源版本。
- [ ] 新 Backend 的真实测试结果单独留档，不能引用旧控制台记录替代。
- [ ] 按总体路线补充第二个可切换 Agent，证明 V0.2 的替换能力。

真实测试次数、容差和失败容忍度必须在执行前写入验收配置，验收后不能为了通过而回改标准。

## 7. P4：SearchTarget 闭环

进入条件：P3 已验收，冻结 F10。

- C 负责搜索任务、检测 baseline、目标报告格式、定位评价；B 提供实际可用的传感器、目标真值或场景接口；A 接入记录和数据传递。
- 首先核实旧场景是否能提供可信目标与真值；如果不可用，记录能力阻塞，先继续 ReachPoint Benchmark，不用 fake detection 冒充真实识别。
- Agent 只获取约定的可见观察；评测真值走独立通道。若做真值辅助 baseline，必须明确标注。
- 固定路线与规则 Agent 使用相同传感器输入条件；目标上报必须有可追踪的事件或动作。

验收：真实感知输入→检测/定位→目标上报→独立真值评价闭环成立；至少含找到、未找到及超时样例。

## 8. P5：Integration 2，V0.3 比较实验

进入条件：至少一个真实任务通过 P3；SearchTarget 只有通过 P4 才进入正式比较。冻结 F11。

- A 提供 ExperimentManager、结果聚合、可读取记录的回放工具和报告。
- B 支持连续 reset/run，记录初始状态、延迟、错误和不可控因素。
- C 提供固定 Benchmark Pack、至少三种有明确差异的 baseline、指标定义与固定实验配置。
- 先做小批重复验证，再扩大 seed/repeat；场景没有随机化能力时只声明固定场景重复或 Agent seed 变化。
- 汇总保留失败分母，区分任务失败与基础设施错误；不能只统计成功 episode。

建议初始关卡：同一任务连续 5 次 reset/run，保留所有结果且每次初态符合约定；通过后做 3 Agent × 5 repeats 的最小比较。这些是待写入验收配置的规划值，不是已获得的稳定性结论。

本阶段回放先指记录重读、轨迹和事件检查；不承诺由录制动作精确重演物理仿真。
