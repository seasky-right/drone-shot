# 插件开发交接（v0.2 候选）

更新日期：2026-09-25。C0-C5 的技术验证范围见[阶段记录](../validation/可插拔Core阶段验证-2026-09-25.md)。C6 的受影响方确认、协议冻结与真实插件作者反馈尚未闭环。以下接口可用于候选插件开发，不代表真实双机或其他仿真引擎已验收。

## 开发入口

公开类型在 `contracts/plugin_v02.py`、`contracts/data_v02.py`；装配在 `core/plugins.py`；独立 Pack 骨架在 `examples/external_plugin/`。插件依赖公开的 `contracts/` 和 `core/` API；Backend Pack 可另依赖底层适配包。Core 不应依赖具体插件或 AirSim RPC。

Pack wheel 声明 `drone.plugins.v02` entry point，将 `drone_plugin.json` 放进顶层包的 wheel RECORD。Manifest 必填 `id/version/type/plugin_api/entry_point/dependencies/capabilities/config_schema`；多组件 Pack 另填 `components`，每项包含稳定 `id/type/entry_point/capabilities/config_schema`。Manifest ID、entry point 名和值、distribution 版本须对应；一个 distribution 当前只允许一个 Pack entry point。Task、Agent、Scenario 可通过 `requires` 声明 Backend 需求。完整示例见 `examples/external_plugin/src/drone_ext_sample/drone_plugin.json`。

工厂接收校验后的 `config` 与受限 `CoreContext`，返回对应角色组件；通用收尾 hook 是 `close()`。Context 仅提供 `episode_id`、`artifacts.write_bytes()`、`emit()`。JSON Schema 中的 `writeOnly` 或 `x-secret` 用于记录时脱敏，相对 artifact 路径用 `format: "episode-relative-path"`。Registry 的 `discover/list/preflight/resolve/effective_config/recordable_config` 在导入工厂前检查 ID、API、依赖、配置和声明能力；`instantiate` 才导入工厂。依赖只校验，不自动安装；`--manifest` 供源码调试，正式安装由 wheel 自动发现。

## 十类组件

| `type` | 最小 hook/数据 | 当前接入 |
| --- | --- | --- |
| `backend` | `capabilities/reset/execute/observe`；返回 `CapabilitySetV02`、`EpisodeSnapshotV02`、`ActionOutcome` | `run-multi` |
| `task` | `complete(snapshot, truth) -> bool`；可有 `action_handlers()` | `run-multi` |
| `agent` | 集中式 `act(snapshot)` 或逐机 `act(observation)` | `run-multi` |
| `scenario` | `ScenarioSpecV02` 或 `.spec`，可附 `.truth` | `run-multi` |
| `runtime_provider` | `acquire(episode_id, request)/release(resource)` | `run-multi` 可选 |
| `evaluator` | `evaluate(result)` 返回有限数值指标 | Conformance；尚未进入 `run-multi` 评分 |
| `scenario_generator` | `generate(seed)` 返回可重复场景 | Conformance；运行配置直接选 Scenario |
| `training_driver` | `run(session_factory)` 重复使用 Session | Conformance |
| `result_processor` | `process(read_result, episode_ids)` 返回 JSON 摘要 | Conformance，只读结果 |
| `benchmark` | `cases()` 返回案例 ID 唯一的 JSON 案例 | Conformance；正式评分另验 |

目前无独立 `resource_provider` 类型。资源由 `ScenarioSpecV02.resources`、Scenario/Runtime Provider 和 Artifact Store 表达。需要通用资源解析或权限语义时须改协议。逐类 hook 输入和反例见[详细说明](README.md)及 `core/conformance_probes.py`。探针通过不证明领域规则、真实传感器或物理资源释放正确。

`ActionV02` 包含 action/vehicle ID、`namespace/name` 类型、`control/sampling/report` 通道、payload schema ID、JSON payload 和时限。运行配置的 `action_schemas` 与 `payload_schemas` 注册动作；未知类型或非法 payload 被拒绝。非控制通道需 Backend 或 Task 提供 `ActionChannel` handler。`PlatformObservationV02` 包含公共状态、传感器 artifact 引用、缺失原因与命名空间扩展；底层 `simulator_contract` 观察不是 Agent 平台观察。Scenario 真值只交 Task，不进入 Agent snapshot。

`ScenarioSpecV02` 记录场景 ID、独立版本、checksum、相对资源路径、seed、初态及真值访问级别；同一场景可组合不同 Task。`EpisodeSnapshotV02` 以稳定 vehicle ID 映射观察与缺失原因，`AgentBindingV02` 绑定 Agent/载具。Backend 的 `CapabilitySetV02` 包含动作、传感器类型及实际资源 ID、坐标/时间、载具上限、场景操作、真值与有界执行。Core 先按 Manifest 预检，构建 Backend 后复核实际能力；声明 RGB 不代表指定相机存在。同步调用无法由 Core 硬抢占，硬取消请求当前被预检拒绝。

## 安装和验证

使用 Python 3.13、Core wheel 及复制到仓库外的 `examples/external_plugin/`。实际独立安装证据见[阶段记录](../validation/可插拔Core阶段验证-2026-09-25.md)。

```powershell
python -m pip wheel <external-plugin-dir> --no-deps --no-build-isolation --wheel-dir <wheel-dir>
python -m pip install <core-wheel> <external-plugin-wheel>
drone-plugins list
drone-plugins preflight <sample.json>
drone-plugins validate-plugin --component-cases <component-cases.json> --sample <sample.json> --output <runs-dir>
drone-plugins run-multi <sample.json> --output <runs-dir>
drone-plugins show-result <episode-id> --output <runs-dir>
```

`validate-plugin` 无样例只查静态元数据，报告 `runtime_checked=false`；带逐类 case 才执行 hook，逐组件报告 `passed/failed/unchecked/unsupported`。内置十个 `drone.v02.mock/*` 有 v0.2 case；另十四个旧组件显式为 v0.1，在 v0.2 探针中为 `unsupported`。受保护 Backend 需在受控环境传 `--enable-backend`，旧单机 CLI 使用 `--enable-airsim`。插件是可信 Python 代码，当前无不可信上传隔离。预检失败先看结构化 code/source/字段路径；运行失败保留 `INCOMPLETE`，成功结果用 `show-result` 重读，v0.1 记录用旧读取器。插件应提供能力不符、缺资源、非法动作及清理失败反例，真实仿真结果单独记录。

## 兼容和 Core 变更

Plugin API `drone.plugin.api/v0.2`、数据 schema `drone.platform.contract/v0.2`、Pack 版本、Scenario 版本和评分政策版本彼此独立。v0.1 Action/Observation 只迁移已知字段；旧配置和结果使用旧解析器。未知字段、未来版本及未知动作拒绝，不猜测迁移。破坏性变更先定义新版本、迁移规则、正反 fixtures 和兼容矩阵，再由受影响插件作者确认；C6 前继续标为候选。

新增任务、算法、Backend、场景、生成器、指标、训练策略或报告通常只需新增 Pack 组件 ID、Manifest、配置及 conformance case。现有数据模型无法表达新运行语义、需要通用组件类别或生命周期 hook、能力协商无法验证资源、需要跨插件权限边界、Session/Store/Registry 缺少实际服务，或发现 Core 错误时，仍可能改 `contracts/` 或 `core/`。以最小外部插件、预期行为和失败证据提出变更，再做版本化协议和回归验证。真实双机、其他引擎、硬抢占、正式 Benchmark 和不可信插件隔离各需独立设计与验收。
