# P2 实现与本地验收报告

日期：2026-09-23。范围：近期开发执行计划的 P2 A/B/C 工作包及一次跨线 Mock 集成。本报告只记录本地实现与验证，不代表 P3 真实仿真验收或真人 track 签字。

## 实现范围

| 工作线 | 本轮交付 | 当前证据 |
| --- | --- | --- |
| A 平台内核 | `core/` 的 EpisodeRunner、Recorder、CLI；Mock 扩展及可切换 Agent。按动作前观察、执行、动作后观察、Task/Evaluator、记录、清理的顺序运行，原始终止原因与 `CleanupResult` 分开。 | Runner 生命周期测试、Mock CLI 成功运行及落盘结果。 |
| B 仿真后端 | `backends/airsim/` 的 AirSimBackend、独立 smoke 入口和配置说明；底层适配器对 RPC `False` 的失败映射。 | FakeRpc 验证连接、重置、起飞、NED 到机体系速度换算、状态确认、传感器缺失、超时和清理失败。未启动真实仿真器。 |
| C 任务与评价 | ReachPointTask、FixedRouteAgent、最小 Evaluator、六类场景 fixture 与规则说明。 | 到点、未到点、超时、执行失败及返航/降落收尾失败样例；评测只输出可得指标。 |
| 跨线集成 | Mock CLI 使用正式 ReachPoint Task/Agent/Evaluator，通过同一平台协议生成配置快照、结果、轨迹和事件。 | `tests/test_p2_cli_integration.py` 和安装后 `drone-run` 运行。 |

P2 继续使用 `drone.platform.contract/v0.1` 的 `move_to`、`hover`。AirSimBackend 的 `reset` 按配置起飞，`cleanup` 负责返航与降落；任务到点与收尾结果独立表达。平台 Core 没有直接导入 AirSim RPC 或冻结课程材料。

- 平台与 P2 测试：`python -B -m unittest discover -s tests -q`，**39/39 通过**。
- 底层适配测试：`python -B -m unittest discover -s simulator_contract/tests -q`，**9/9 通过**。
- `python -B scripts/verify_dependency_lock.py` 通过。
- 本地构建 wheel 并运行 `scripts/verify_wheel.py`，包范围检查通过；在独立虚拟环境安装 wheel，从 `site-packages` 加载 `core`、`backends.airsim`、`tasks.reachpoint`，执行 `drone-run` 得到成功的 Mock ReachPoint 结果。
- 真实 UE4/AirSim **未运行**。B 的 smoke 入口已提供，真实控制、传感器和安全收尾仍须在 P3 单独留证据。

## 基线完整性检查

`python -B simulator_contract/freeze_baseline.py --verify` 当前返回 `BASELINE_MISMATCH`。只读比对发现清单记录的 1,389 项中，当前有 1,383 项；差异仅为冻结课程目录 `PythonClient/.pytest_cache/` 下缺少的 6 个缓存文件，仍存在的 1,383 项哈希与大小全部一致。此次未写入或重建冻结目录、`airsim-settings/drone.json` 或 manifest，也未运行 baseline writer。该差异须作为独立基线维护事项核实，不能把本轮 P2 记为“冻结基线校验通过”。

## P3 之前的待验收项

1. 按 F07 在实际场景运行独立 B smoke，记录场景/客户端版本、载具与相机标识、动作后状态和异常；FakeRpc 结果不能替代真实飞行。
2. 按 F08 冻结真实 ReachPoint 航点、高度、速度、到达容差、时间预算与整体验收条件；明确兼容性近地降落能否作为安全收尾通过。当前 `near_ground_disarmed_compatibility` 不证明实际触地。
3. Runner 与 AirSimBackend 合流前统一传感器文件根目录：`SensorReference.relative_path` 必须指向 episode 目录内的文件。B 独立 smoke 已能保存二进制样本，Runner 集成路径尚未验收。
4. 同步 `execute` 的动作期限只能在调用返回后判定，无法抢占卡住的 RPC；真实超时与恢复行为需另行验证。
5. 旧场景未提供可信碰撞数据时，Evaluator 不输出零碰撞结论；若将无碰撞设为硬条件，需先补可验证数据源。

P2 的本地代码与无仿真集成已完成；P3 真实闭环和真人确认尚未完成。
