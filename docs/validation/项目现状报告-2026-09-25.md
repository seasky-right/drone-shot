# 项目现状报告（2026-09-25）

## 结论

项目已具备按 Plugin Contract v0.2 **候选协议**并行开发、独立安装和逐组件测试插件的基本 Core。Core/Contracts 与内置 Pack 分别构建 wheel；仓库外整套 Pack 和仅含一个 Agent 的独立 wheel 均已被未改动的 Core 发现、预检和测试。单 Agent wheel 可与内置 Backend、Scenario、Task 组成双机 Mock episode，成功结果可重读。因此后续插件作者可以从公开协议和样例开始，不必预先修改 Core。

这不是“任意插件无需适配即可运行”的承诺。运行组合必须满足动作、传感器、场景、载具数、配置和依赖协议。Plugin API `drone.plugin.api/v0.2` 与数据 schema `drone.platform.contract/v0.2` 尚待实际插件作者反馈与受影响方确认，C6 未完成；跨插件通用语义出现缺口时仍需修改并版本化 Core。代码基线从本地提交 `0e24f11` 起，旧[2026-09-24 现状报告](项目现状报告-2026-09-24.md)作为迁移前快照保留。

## 已有能力与边界

| 范围 | 当前实现 | 尚不能据此宣称 |
| --- | --- | --- |
| 发现与装配 | wheel 中的 `drone.plugins.v02` entry point 和静态 `drone_plugin.json`；Registry 在导入工厂前检查 ID、版本、依赖、JSON Schema、声明能力和配置 | 自动安装依赖、隔离不可信 Python 插件 |
| 数据与组合 | 命名空间 Action、可扩展平台 Observation、独立 Scenario、稳定 vehicle ID、Agent 绑定、声明与运行时两阶段能力核对 | 任意动作自动转换、真实多机飞行、传感器物理存在 |
| 生命周期与记录 | Session/Runner 共用事件与终止机制；取消/超时/清理、Runtime 获取释放、Artifact/Result Store、`INCOMPLETE` 和结果重读 | 同步 RPC 硬抢占；要求硬取消的组合目前在预检拒绝 |
| 可运行组合 | v0.2 `backend`、`scenario`、`task`、`agent`、可选 `runtime_provider` 由 `run-multi` 装配 | 其余类型均已进入统一业务流程 |
| 可单独测试的类型 | `evaluator`、`scenario_generator`、`training_driver`、`result_processor`、`benchmark` 及上述五类都有逐类可执行 conformance 探针 | 探针通过等于正式评分、训练、报告或领域正确性 |
| 旧组件迁移 | 14 个 v0.1 内置组件经显式适配保留；指定 UE4/AirSim 单机成功和可控失败有安装版迁移回归 | v0.2 AirSim 双机、第二仿真引擎或 P3/F07/F08 正式验收 |

内置 Pack 的十个 `drone.v02.mock/*` 组件提供 Mock 开发搭配，但运行配置必须显式选择 Backend、Scenario、Task 和至少一个 Agent，不存在自动选取的默认组合。新插件只替换其中一个角色时，仍须与其他角色的公开能力和动作 schema 匹配。接口、Manifest、配置和错误规则见[插件开发交接](../plugins/插件开发交接.md)及[详细开发说明](../plugins/README.md)。

## 下一步

各作者先给出组件 ID、Manifest、配置 schema、能力需求、最小 conformance case 和独立 wheel，再用内置 Mock 或外部 Pack 做最小混装。随后分别开发 v0.2 AirSim/其他 Backend、Scenario/Resource、SearchTarget、Evaluator/Benchmark 与协同策略；正式场景运行、真值隔离和评分另留证。`evaluator`、`scenario_generator`、`training_driver`、`result_processor`、`benchmark` 的统一运行接线是后续通用编排工作，不能把现有探针当作完成的业务流程。

C6 要用实际插件作者反馈审定候选协议，再决定冻结或版本升级。F07/F08、P3、SearchTarget 和正式 Benchmark 仍分别按原验收线办理。冻结课程材料、`airsim-settings/drone.json` 与旧场景 manifest 保持原路径和字节；未运行 baseline writer。wheel、venv 和运行结果留在 Git 忽略目录，源码提交只包含小型样例、测试及验证摘要。
